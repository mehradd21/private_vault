# مستند امنیتی

## هدف

هدف این طراحی این است که عکسها و ویدئوهای کاربر بدون رمز عبور قابل خواندن نباشند، در گالری یا فایلمنیجرهای عادی دیده نشوند و هنگام رفتن اپلیکیشن به پسزمینه بلافاصله قفل شوند.

## اقدامات پیادهشده

| مورد | پیادهشده |
|---|---|
| ذخیرهسازی خصوصی | تمام فایلها در `Context.getFilesDir()/vault` و subdirectory های آن قرار دارند. از حافظهٔ عمومی و `Android/data` استفاده نمیشود. |
| رمزنگاری | AES-256-GCM به صورت چانکهای ۲۵۶ کیلوبایتی؛ Nonce تصادفی ۹۶ بیتی و Tag ۱۲۸ بیتی مستقل برای هر چانک. |
| تشخیص دستکاری | هدر و شمارهٔ چانک به عنوان AAD استفاده میشوند. تغییر، حذف یا جابهجایی چانک باعث خطای اعتبارسنجی میشود. |
| مشتقسازی کلید | Argon2id با `t=3`، `m=32768 KiB`، `p=2`. رمز عبور هیچگاه مستقیماً کلید AES نیست. |
| مدیریت کلید | VMK تصادفی توسط کلید مشتقشده پوشیده میشود. روی اندروید کپی دوم آن توسط Android Keystore پوشیده و هنگام ورود بررسی میشود. |
| ذخیرهٔ رمز عبور | رمز عبور ذخیره نمیشود؛ فقط envelope رمزنگاریشده نگه داشته میشود. |
| قفل | `on_pause`، `on_stop`، `ACTION_SCREEN_OFF`، بازگشت از Recent Apps، قفل دستی و قفل خودکار بعد از عدم فعالیت، همگی session را میبندند. |
| پاکسازی حافظه | VMK و کلیدهای مشتقشده از نوع `bytearray` هنگام قفل یا بعد از استفاده صفر میشوند. |
| FLAG_SECURE | از Screenshot، ضبط صفحه و نمایش محتوا در Recent Apps جلوگیری میشود. `TaskDescription` خنثی تنظیم شده است. |
| بندانگشتیها | thumbnail تصاویر رمزنگاری میشود و فقط هنگام باز بودن قفل رمزگشایی میشود. |
| فایلهای موقت | در پوشهٔ خصوصی `vault/temp` با مجوز محدود ایجاد و بعد از استفاده حذف میشوند. حذف «باز کردن با» تا بازگشت نتیجه به تعویق میافتد. |
| اشتراکگذاری | FileProvider با دامنهٔ محدود به `vault/temp/` و grant موقت فقط برای خواندن. |
| اعتبارسنجی ورودی | نوع فایل با ترکیب پسوند، MIME و magic bytes تعیین میشود؛ تکیه بر پسوند به تنهایی کافی نیست. |
| اتمیک بودن Import | فایل ابتدا در `.part` رمزنگاری و کاملاً اعتبارسنجی میشود، سپس با `os.replace` به نام نهایی منتقل میشود. |
| حذف اصل | حذف نسخهٔ اصلی فقط پس از تأیید صریح کاربر و بعد از موفقیت Import انجام میشود. |
| لاگها | رمز عبور، کلیدها و محتوای فایلها لاگ نمیشوند. فیلتر logcat در buildozer تنها پیامهای Python را نگه میدارد. |
| پشتیبانگیری | `android.allow_backup = False` است تا کلیدها و فایلها وارد پشتیبان گوگل نشوند. |

## قالب encrypted file

```text
PVA1 | version | chunk_size | plain_size | [nonce | ciphertext+tag] ...
```

Authentication Tag هر چانک مستقل است و AAD شامل هدر و شمارهٔ چانک میباشد. بنابراین truncate و reorder کردن فایل شناسایی میشود.

## فرمت key envelope

```text
PVK1 | version | flags | argon2_mem | argon2_time | parallelism
    | salt(16) | nonce(12) | wrapped_vmk(32) | tag(16)
    | [keystore_nonce(12) | keystore_wrapped_vmk(32) | tag(16)]  (اختیاری)
```

تغییر رمز عبور فقط قسمت `wrapped_vmk` را عوض میکند و VMK ثابت میماند.

## مدل تهدید

### در محدودهٔ محافظت

- فایلمنیجرها و گالری اندروید محتوای اصلی را نمیتوانند ببینند.
- برنامهٔ دیگری بدون رمز عبور نمیتواند فایلهای `.enc` را رمزگشایی کند.
- Screenshot و ضبط صفحه از صفحات حساس مسدود است.
- محتوای صفحات در Recent Apps دیده نمیشود.
- فایل موقت باز کردن با، پس از پایان استفاده حذف میشود.
- تلاشهای مکرر رمز عبور منجر به تأخیر موقت میشود.

### خارج از محدودهٔ محافظت

این اپلیکیشن **ادعا نمیکند** که در برابر موارد زیر ایمن است:

- دسترسی Root یا دسترسی فیزیکی پیشرفته به device.
- استخراج حافظهٔ پردازش یا حملات side-channel.
- حذف کامل اپلیکیشن توسط کاربر یا ابزارهای مدیریت دستگاه.
- بدافزاری که هنگام باز بودن قفل، بر روی همان دستگاه اجرا شود.
- از دست رفتن رمز عبور توسط کاربر؛ در این صورت VMK قابل بازیابی نیست.

## توصیهها به کاربر

- رمز عبور حداقل ۸ کاراکتر و ترجیحاً طولانی و منحصر به فرد انتخاب کنید؛ این رمز عبور تنها وسیلهٔ بازیابی VMK است.
- از پشتیبانگیری عمومی از پوشهٔ خصوصی اپلیکیشن خودداری کنید.
- گزینهٔ «حذف نسخهٔ اصلی» را تنها زمانی تأیید کنید که خروجی encrypted vault را تأیید کردهاید.
- قبل از حذف نسخهٔ اصلی، از سالم بودن فایل داخل vault اطمینان حاصل کنید.
- پس از اتمام «باز کردن با»، برنامهٔ مقصد را ببندید تا فایل موقت پاک شود.

## وضعیت بررسی

بررسیهای مستقل در `TEST_REPORT.md` مستند شدهاند. تستهای کامل روی دستگاه واقعی اندروید (بررسی مسیرها، رفتار Recent Apps و SAF) پس از ساخت APK و در اختیار گرفتن دستگاه باید تکمیل شوند.
